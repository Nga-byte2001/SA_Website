# Apple-design interface audit 001

Date: 2026-09-13  
Scope: `index.html`, four policy detail pages, shared CSS, and shared JavaScript  
Mode: AFTER — the request to audit and fix all issues pre-approved every in-scope finding.

## Design read

Odyssey is a bilingual student election campaign with supplied banner, logo, and cabinet photography. The visual language is editorial and nautical: deep blue-green water, campaign orange, warm paper-colored text, high-contrast display typography, and restrained route/line motifs. The redesign keeps those real assets as the focal point. Cormorant Garamond carries campaign headlines, DM Sans keeps controls and English body copy legible, and Noto Serif TC supports the Chinese content. Translucency is reserved for the navigation layer; price and policy structures use borders and rhythm rather than decorative cards.

## Findings and resolutions

1. **High — The home hero clipped and overwhelmed phone layouts.** The banner, campaign panel, CTA, and countdown did not form a stable hierarchy at narrow widths. **Resolved:** introduced a content-driven phone composition, an editorial three-column desktop composition, bounded typography, a four-unit countdown grid, and breakpoint-specific spacing.
2. **High — Muted text and primary-action contrast were below a dependable accessibility bar.** Several labels relied on low-alpha cream and the CTA foreground initially failed AA. **Resolved:** replaced alpha text tokens with solid accessible colors, strengthened structural lines, and changed the CTA to `#162e3e` on `#e8773a` (4.77:1).
3. **High — The closed mobile menu remained reachable by keyboard.** It lacked dialog state, focus containment, focus return, and a reliable escape route. **Resolved:** added dialog semantics, `aria-hidden`, `inert`, focus trapping, Escape/close behavior, focus restoration, explicit 44px-plus controls, and automatic closure when crossing to desktop.
4. **Medium — Navigation lost legibility over campaign artwork.** **Resolved:** placed it on one consistent dark material with blur/saturation, a stronger scrolled state, visible Menu labeling, and current-page wayfinding.
5. **Medium — Motion was repetitive and did not fully respect user preferences.** **Resolved:** grouped hero and page-title entrances, shortened feedback, reduced hover travel/scale, kept transitions interruptible, and added reduced-motion fallbacks with no spatial travel.
6. **Medium — Policy pages were spacious collections of near-identical floating cards.** **Resolved:** tightened section rhythm, flattened repeated containers, used rules and aligned rows for policy detail, and retained distinct grouping only where comparison materially helps.
7. **Medium — Keyboard and assistive-technology structure was incomplete.** **Resolved:** added skip links, named navigation, main landmarks, descriptive page metadata, a named countdown timer, visible focus treatment, and meaningful button labels.
8. **Low — Phone grids and long bilingual headings could overflow or become cramped.** **Resolved:** made every detail grid single-column at phone width, bounded heading sizes, reduced tracking where needed, and removed brittle fixed spacing.
9. **Low — External new-tab links lacked defensive relationship attributes.** **Resolved:** added `rel="noopener noreferrer"` everywhere `target="_blank"` is used.
10. **Low — The project documentation described the former Tailwind/GSAP single-page implementation.** **Resolved:** documented the current five-page, dependency-free shared CSS/JavaScript structure.
11. **Low — The favicon declared PNG content even though the supplied logo file contains JPEG data.** **Resolved:** corrected the declared MIME type on every page and documented the historical filename accurately.

## Verification record

- Browser Use visual audit: desktop home, desktop Services, 390×844 home, and open mobile navigation.
- Browser Use interaction audit: menu opens into the close control, reports `aria-expanded=true`, removes `inert`, closes on Escape, and returns focus to the opener.
- Keyboard audit: skip link becomes visible on focus; mobile navigation focus stays inside the dialog.
- Contrast checks: cream/night 10.51:1; muted/night 8.35:1; faint/teal 4.82:1; orange/night 4.77:1; light accent/teal 4.91:1.
- Automated local checks: HTML parsing, local link/asset resolution, required page landmarks, missing alt text, target/rel pairing, and JavaScript syntax.

## Delivery gate

- **PASS — Hierarchy:** campaign art leads, the hero panel bridges image to information, and detail pages scan by section and rule.
- **PASS — No excessive rounded UI:** structural surfaces are squared; only portrait imagery retains its natural circular crop.
- **PASS — No gradients:** palette uses solid campaign colors and a single translucent navigation material.
- **PASS — No decorative badges/pills:** no badge-shaped section labels or rounded text containers.
- **PASS — Restraint:** orange is reserved for emphasis, actions, route markers, and focus.
- **PASS — Typography:** campaign display face, readable body face, and Chinese serif are used consistently.
- **PASS — Motion:** transitions explain entry, continuity, hover feedback, and menu state; reduced motion is supported.
- **PASS — Accessibility:** semantic landmarks, keyboard navigation, focus visibility, contrast, touch targets, and user display preferences are covered.
- **PASS — Mobile:** no horizontal overflow at the audited phone viewport; navigation and grids reflow by content priority.
- **PASS — Assets:** existing campaign banner, logo, and member photography are used; no substitute stock or generated imagery was introduced.
